# 考试系统使用说明

本项目的考生界面是中文，研究者后台和统计界面是英文。首页直接进入考生登录，版权署名为廖鹏宇。

## 本地启动

在本项目目录打开 PowerShell：

```powershell
npm install
npm run setup
npm run dev
```

打开 `http://localhost:3000/admin/`。`npm run setup` 已将随机管理员密码写入项目根目录的 `.env.local`，复制其中 `ADMIN_PASSWORD=` 后面的值到后台登录框。API Key 放在同一文件的 `GEMINI_API_KEY=` 后面，保存后重新启动服务。不要将整个文件发给任何人，也不要放入 GitHub。

## 正式组织一次测试

1. 后台 **Settings**：设置学习分钟数、每次考试限时和延迟天数。默认学习 120 分钟、每次考试 25 分钟、延迟 7 天。有人同意参与后参数锁定，因此先检查清楚。
2. 后台 **Question Bank**：核对三套试卷的日语、答案和评分规则。每套 15 题，每个维度 3 题。题目是原创研究用题，不等同于经过效度验证的标准化试卷。
3. **Participants**：输入 10，选择反馈方式，然后 **Create codes**。下载参与码表格，分别发送每个人自己的参与码和考生网址。随机分三组只适合流程预试，十人的样本不能支撑可靠的三组效果结论。
4. 考生登录后填写知情同意和资料，按顺序完成考试、学习和问卷。延迟后测在即时后测提交后的设定时间开放。测验不提供 AI 入口，学习环节提供有限反馈。
5. **Scoring**：填写评分者编号，按参考规则给开放题打 0–4 分。未评分的答案保持缺失值，不会自动变成零分。参考答案仅为示例，要接受其他正确表达。
6. **Exports**：导出 CSV 和私人 JSON 备份。点击 **Load complete cases into analysis** 再打开 **Open analysis dashboard**。目前统计面板只使用所有阶段和问卷齐全且评分完成的记录；未完成者仍保留在原始导出中。

## 补充题库

在 **AI Generation** 中选择试卷、维度和主题，生成 3 道草稿。在 **Question Bank** 审核、修改 JSON，指定替换同一试卷同一维度的哪一题，勾选人工审核后发布。也可以导入自己整理的 JSON 草稿。有人开始前测后正式题库锁定。

联网生成通过服务器调用 Gemini，不是从互联网上抓取题目，也不会自动发布。AI 失败会提示错误，不会假装生成成功。`GEMINI_MODEL` 可以按账户可用模型修改。

## 部署需要什么

GitHub Pages 只能放前端，不能保管 API Key 或集中存十个人的答卷。完整在线使用需要 Vercel 或自有服务器。Vercel 必须另外配置 Redis REST 持久存储，环境变量见根目录 `.env.example` 和 README。自有单进程服务器可使用本地文件持久保存。

Vercel 部署成功后，将真实 API 地址填入 GitHub 仓库变量 `RESEARCH_API_URL`，例如 `https://你的域名/api/research`，重新运行部署工作流。没有服务端地址时，GitHub Pages 会明确提示未连接收卷服务器。

## 注意事项

- 开始前统一设备、网络、测试环境和外部工具规则；软件不能证明考生没有使用其他 AI。
- 计时不会因关闭网页暂停。超时后仅接受截止前已同步到服务器的答案。没有网络时，本机暂存不等于已收卷。
- “对话应答”目前是文字题，不能当作口语或发音结果汇报。
- 时长记录是整个阶段耗时，不是逐题反应时；学习时长是经过时间，不保证持续专注。
- 旧的第一轮文件不会自动进入新数据；请对照原始答卷核验其来源。
- 数据撤回可在 **Settings → Withdraw participant data** 中操作；已导出的文件需另外处理。
- 本地数据保存在 `.research-data/study.json`，应私下备份；不要推送答卷或参与码到公开仓库。
